Generated by `tests/test_crisis_eval.py --report` against `tests/crisis_eval_set.json`.

## Why this matters

`api/crisis.py` screens every user message in code before the language model is called. If it classifies a message as **high**, the app bypasses the model entirely and returns verified helplines. That makes **recall on high-risk messages** the safety-critical number: a false negative means someone in crisis gets a normal chatbot reply. Precision matters too, because a false alarm replaces the model's reply and interrupts the conversation. The classifier is deliberately tuned for recall first, precision second.

## Baseline before hardening (for comparison)

The same 101-case set was first run against the original pattern list (2026-09-12) to find the gaps before any changes were made:

| Metric | Before | After |
|---|---|---|
| High-risk recall | 70.7% (12 missed) | 100.0% (0 missed) |
| High-risk precision | 80.6% (7 false alarms) | 100.0% (0 false alarms) |
| 3-class accuracy | 74.3% | 99.0% |

What the baseline missed: passive ideation phrased without the word *die* ("better off without me", "rather be dead", "not worth living", "want it all to end"), "do not" spelled out instead of "don't", pill overdoses without the word *overdose*, and every Hinglish phrasing. What it over-triggered on: "don't want to live **in** this hostel", "die **of embarrassment**", "cut myself **while** chopping", "hurt myself **at** the gym", "overdose **on coffee**". Each of those became a negative-lookahead or a negation rule in `api/crisis.py`.

## How to extend

1. Add a case to `tests/crisis_eval_set.json` with the *ideal* label.
2. Run `py -m pytest tests/test_crisis_eval.py -q`. The suite fails if any high-risk case is missed or if high-risk precision drops below 90%.
3. Adjust the patterns in `api/crisis.py`, re-run, then regenerate this file with `--report`.
